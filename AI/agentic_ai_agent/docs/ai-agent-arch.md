질문하신 개념들은 Anthropic이 자사의 대표 AI 모델인 Claude와 개발 툴(Claude Code, Managed Agents 등)을 중심으로 정립하고 고도화해 온 **현대적인 AI 에이전트 아키텍처의 핵심 인프라와 작동 메커니즘**을 구성하는 요소들입니다.

기존의 모호하고 추상적인 에이전트 개념을 엔지니어링 수준에서 실체화한 이 개념들을 하나씩 명확하게 설명해 드리겠습니다.

---

## 1. AGENTS.md (또는 SKILL.md)

**AGENTS.md**(그리고 실제 Anthropic의 표준 스펙으로 명문화된 **SKILL.md**)는 AI 에이전트에게 특정 역할, 전문 지식, 수행 가능한 워크플로우를 주입하기 위해 작성하는 **텍스트 기반의 규칙 가이드 파일**입니다.

* **개념:** 기존 소프트웨어의 '설정 파일(Configuration)'과 유사하지만, 사람이 읽는 자연어와 메타데이터(YAML) 형식으로 작성됩니다.
* **작동 방식:** 에이전트가 구동될 때 수많은 기술 폴더 중 이 파일의 `name`과 `description`만 먼저 읽어 들여 자신이 처리할 수 있는 일인지 '탐색'합니다. 사용자의 요청이 일치하면 그제야 파일 내부의 상세 지침을 컨텍스트(Context Window)에 로드하여 실행합니다.
* **의의:** 매번 거대한 시스템 프롬프트를 통째로 모델에 집어넣어 비용을 낭비하는 대신, 필요한 순간에만 전문 동적 지침을 불러오게 함으로써 컨텍스트를 극도로 효율적으로 관리합니다.

---

## 2. Skill (스킬)

스킬은 에이전트가 특정 도메인의 작업이나 정형화된 비즈니스 프로세스를 일관되게 수행할 수 있도록 자연어 지침, 참조 자료, 실행 스크립트, 템플릿 등을 하나로 묶어둔 이식성 높은 패키지(폴더)입니다.

* **개념:** 개발자 관점에서는 일종의 '플러그인'이나 '라이브러리'에 가깝습니다.
* **특징:** 예를 들어 '법률 문서 검토 스킬', '웹 앱 테스트 스킬', '회사 브랜드 가이드라인 적용 스킬' 등을 독립된 폴더 형태로 구축해 두고 에이전트에게 로드하여 사용합니다.
* **가치:** 에이전트가 임의로 행동(할루시네이션)하는 것을 방지하고, 팀이나 기업 내에서 일관되고 검증 가능한 방식으로 AI 워크플로우를 재사용하고 공유할 수 있게 합니다.

---

## 3. SubAgent (하위 에이전트)

하위 에이전트는 복잡하고 거대한 메인 태스크를 해결하기 위해, **주요 에이전트(Parent Agent)에 의해 생성되거나 호출되어 특정 전문 작업만 격리된 채 수행하는 독립적인 격리형 에이전트**입니다.

* **개념:** 회사에서 총괄 팀장이 복잡한 프로젝트를 처리할 때, 기획서 작성은 '기획 담당자'에게, 코딩은 '개발 담당자'에게 완전히 위임하는 구조와 같습니다.
* **작동 방식:** 메인 에이전트의 컨텍스트 윈도우를 오염시키지 않기 위해, 하위 에이전트는 자신에게 할당된 컨텍스트와 전용 스킬(Skill)만 가지고 독립된 루프를 돌며 문제를 해결한 뒤 최종 결과만 메인 에이전트에게 보고합니다.
* **의의:** 프롬프트가 너무 길어지면 인지 능력이 떨어지는 LLM의 한계를 극복하기 위해 '태스크 격리'와 '권한 위임'을 아키텍처적으로 구현한 것입니다.

---

## 4. Sandbox (샌드박스)

샌드박스는 AI 에이전트가 안전하게 코드를 실행하고, 파일을 수정하거나, 외부 명령을 실행할 수 있도록 제공되는 안전하게 격리된 가상 실행 환경(클라우드 컨테이너 또는 자체 호스팅 컨테이너)입니다.

* **개념:** 에이전트에게 "코드를 직접 짜서 결과를 확인해 봐"라고 제어권을 줄 때, 에이전트가 개발자의 실제 PC 시스템을 망가뜨리거나 보안 사고를 내지 않도록 보호막을 쳐둔 가상 공간입니다.
* **Anthropic의 혁신 (Decoupling):** Anthropic은 에이전트의 '두뇌(LLM)'와 '손(Sandbox/Harness)'을 완벽히 분리했습니다. 에이전트는 샌드박스를 일종의 API 도구처럼 호출(`execute(tool, input) → result`)하여 사용할 뿐이며, 만약 코드를 실행하다가 크래시가 나거나 컨테이너가 죽더라도 두뇌는 멀쩡히 살아남아 새 샌드박스를 즉시 프로비저닝(생성)하고 작업을 재시도합니다.

---

## 5. MCP (Model Context Protocol, 모델 컨텍스트 프로토콜)

**MCP**는 Anthropic이 주도하고 현재 오픈소스로 표준화(Linux Foundation 산하 기단 이관)된 기술로, **AI 모델(클라이언트)이 데이터소스, 개발 도구, 엔터프라이즈 시스템(서버)과 양방향으로 데이터를 안전하게 주고받을 수 있도록 만든 유니버설 오픈 표준 프로토콜**입니다.

* **개념:** 전자기기 생태계를 통합한 'AI 업계의 USB-C 포트'라고 생각하시면 됩니다.
* **해결하는 문제:** 과거에는 Claude를 Slack, GitHub, Postgres DB, Google Drive 등에 각각 연결하기 위해 매번 커스텀 API 커넥터를 만들어야 했습니다($N \times M$ 연동 문제). MCP는 하나의 표준 규격을 제공하여, 어떠한 외부 시스템이든 MCP 서버 스펙으로 열어두면 Claude나 다른 LLM 앱들이 즉시 그 안의 리소스(Resource), 도구(Tool), 프롬프트(Prompt)를 직관적으로 이해하고 제어할 수 있게 합니다.

---

## 6. Feedback loop (피드백 루프)

피드백 루프는 에이전트가 어떤 행동을 취한 후 **그 결과물이나 외부 환경의 반응을 다시 입력(Input)값으로 받아들여, 다음 행동을 교정하고 점검하는 순환형 제어 프로세스**입니다.

* **개념:** "목표 설정 ➔ 실행 ➔ 결과 평가 ➔ 오류 인지 및 계획 수정 ➔ 재실행"의 자율적 반복 과정을 의미합니다.
* **구현 사례:** Anthropic 프레임워크에서의 ReAct(Reasoning + Acting) 아키텍처나 Reflexion 기법이 대표적입니다. 에이전트가 샌드박스에서 코드를 실행했다가 에러 메시지를 마주하면, 그 에러 메시지를 피드백 루프로 삼아 코드를 스스로 디버깅하는 능력이 이에 해당합니다.

---

## 7. Human-in-the-loop (HITL, 인간 참여형 루프)

Human-in-the-loop는 에이전트가 모든 과정을 100% 자율적으로 처리하게 두는 것이 아니라, **중요한 의사결정이나 위험한 행동을 하기 직전에 강제로 인간의 승인(Approval)이나 개입을 받도록 설계된 안전 장치이자 협업 모델**입니다.

* **개념:** 자율주행차가 운전하다가 위험한 구간에서 운전자에게 운전대를 넘기거나 승인을 요구하는 것과 같습니다.
* **적용 분야:**
* **비용 및 안전:** `git push`를 하거나 시스템 인프라를 변경하는 명령, 외부 메일을 실제로 발송하는 행위, 비용이 크게 발생하는 유료 API 호출 직전.
* **스티어링(Steering):** 에이전트가 복잡한 장기 작업을 수행하는 도중(Mid-execution), 사람이 중간에 인터럽트(개입)를 걸어 "그 방향 말고 이 방향으로 수정해 줘"라고 가이드를 주어 궤도를 수정하는 행위.



---

### 구성 요소들의 유기적 관계 요약

Anthropic의 자율형 에이전트 인프라인 **Managed Agents** 환경에서 이 요소들은 다음과 같이 맞물려 돌아갑니다.

> 유저가 에이전트에게 대규모 프로젝트를 명령하면, 에이전트는 먼저 **AGENTS.md/SKILL.md**를 읽어 도메인 지식을 갖춘 **Skill**을 활성화합니다.
> 작업이 너무 방대하면 **SubAgent**를 생성하여 일을 쪼개어 맡깁니다. 이 과정에서 안전하게 격리된 가상 공간인 **Sandbox** 안에서 코드를 짜고 실행해 보며, 외부 데이터나 툴이 필요할 때는 표준화된 **MCP**를 통해 안전하게 데이터를 가져옵니다.
> 스스로 실행 결과를 검증하는 **Feedback loop**를 돌며 오류를 수정하다가, 코드를 메인 서버에 최종 배포하거나 인프라를 바꿀 때는 **Human-in-the-loop** 가동을 통해 인간의 최종 승인을 받고 안전하게 작업을 마무리합니다.
